# Version 2.4.0

Previous version: 2.3.1
New version: 2.4.0
Diff basis: release/2.3.2..HEAD plus working tree
Version action: minor
SemVer rationale: The payload changes installed workflow surface content in backward-compatible ways — host-specific invocation syntax, sharper skill descriptions, a new truth-doc template section — which the decision table classifies as a generated-surface capability change rather than a fix.

Release payload:

- Workflow skill, rule, and prompt descriptions now advertise only the invocation syntax the generating host accepts, instead of listing every host's trigger on every surface.
- Skill frontmatter descriptions state what each workflow does before when to use it, so hosts selecting among many skills get both signals.
- `SKILL.md` lists its support files under a Reference files heading with named Markdown links and a read trigger for each, and quick procedures no longer repeat the instruction-authority rule that already lives in `support/procedure.md`.
- Typed engineering truth-doc templates carry a `Product Truth Links` section, and the decisions check no longer demands `Current Implementation Behavior` from contract, architecture, workflow, operations, and test-behavior docs whose own kind sections already state current behavior.
- Route file templates explain that every `## ` heading declares an area except `## Source References`, and the matching area diagnostic now says the same thing when a heading is parsed as a malformed area.
- Area index containment checks use the platform path separator, so nested area files resolve correctly on Windows.
- Removed the standalone per-workflow skill renderers and other unreferenced exports (`src/markdown/discovery.ts`, `readBaseFile`, `renderAreasTemplate`, `renderBehaviorLeafDocTemplate`, the hardcoded truth-doc template path constants, `truthLaneRoots`, `PRODUCT_TRUTH_KINDS`, `ENGINEERING_TRUTH_KINDS`, `TRUTHMARK_PORTAL_EXPLICIT_INVOCATIONS`). Installed surfaces have come from `renderTruthmarkSkillPackage` for some time, so those renderers were a second rendering path no host received.
- The host argument to the workflow description renderer is required, so no generated surface can advertise a bare workflow id in place of real invocation syntax.

User-facing release text:

- Installed workflow skills now show only the invocation syntax your host actually accepts, describe what each workflow does as well as when to use it, and link their support files by name. Engineering truth-doc templates gain a `Product Truth Links` section, and route templates and diagnostics explain how area headings are parsed. Nested area files resolve correctly on Windows.

Verification:

- `npm run release:check`
- `truthmark init` regenerated every configured host surface and `truthmark check` reported no diagnostics.
- Repository tests run on Windows; symlink-dependent cases are skipped there through a shared platform helper.
